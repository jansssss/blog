# ohyess 정적 콘텐츠 운영 기준

## 단일 관리 원본

- 모든 정적 금융 가이드는 `lib/guide-content.ts`의 `STATIC_GUIDES`에 한 번만 등록한다.
- 필수 필드는 URL, 제목, 설명, 태그, 클러스터, 아이콘, 목록 순서다.
- 신규 콘텐츠는 `publishedAt`과 `reviewedAt`을 `YYYY-MM-DD` 형식으로 반드시 기록한다.
- 홈페이지 제목·설명이 본문 제목과 달라야 할 때만 `homeTitle`, `homeDescription`을 사용한다.

## 노출 규칙

- 발행 후 21일 동안 가이드 목록과 홈페이지 카드에 `NEW`를 자동 표시한다.
- 가이드 목록은 신규 콘텐츠를 먼저 보여주고 이후 기존 큐레이션 순서를 유지한다.
- 홈페이지는 발행일이 있는 최신 콘텐츠를 우선해 최대 12개만 노출하며, 데스크톱에서는 4열 × 3행으로 배치한다.
- 13번째부터는 홈페이지에서만 밀려난다. 정적 페이지, 사이트맵, 내부 링크와 `/guide` 전체 목록에서는 계속 유지한다.
- 아직 발행일 메타데이터가 없는 기존 콘텐츠는 `homeRank` 순서로 빈자리를 채우고, 이후 전체 가이드 순서로 12개를 완성한다.
- 홈페이지에 오래 남길 콘텐츠는 검색량보다 사용자 가치, 전환 동선, 기존 허브의 대표성으로 결정한다.

## 콘텐츠 생애주기

1. 발행 전: 검색 의도 중복과 키워드 잠식을 확인하고 공식 1차 자료를 최소 2개 교차검증한다.
2. 발행 시: 홈 또는 가이드 목록, 관련 허브, 기존 문서 2~4개, 계산기로 왕복 링크를 만든다.
3. 7~14일: 색인, canonical, 구조화 데이터, 모바일 렌더링을 확인한다.
4. 28~42일: GSC의 노출·검색어·평균순위로 최초 평가한다. 성과가 약하면 새 글을 복제하지 말고 제목·답변 구조·내부 링크를 개선한다.
5. 정기 검토: 일반 가이드는 90일, 규정·금리·정책 의존 페이지는 30일마다 사실관계를 재확인한다.
6. 통합 또는 종료: 같은 검색 의도의 문서가 겹치면 강한 문서로 합치고 이전 URL은 301 리디렉션한다. URL 삭제만 하는 방식은 금지한다.

## 클러스터와 내부 순환

- 클러스터는 `대출 한도`, `주택담보대출`, `금리·상환`, `신용·심사`, `전세·보증`을 기본으로 한다.
- 신규 페이지는 상위 허브 1개, 관련 정적 가이드 2~4개, 실제 행동을 돕는 계산기 1개 이상과 연결한다.
- 관련 기존 페이지에서도 신규 페이지로 돌아오는 링크를 추가해 한 방향 링크로 끝나지 않게 한다.

## 매 배포 검증

```bash
npm run check:sitemap
npm test
npx tsc --noEmit
npm run build
git diff --check
```

하나라도 실패하면 커밋하거나 푸시하지 않는다. GSC 근거가 부족하면 저품질 신규 페이지를 억지로 만들지 않고 그 회차를 보류한다.
